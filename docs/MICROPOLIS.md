# Micropolis AI 시장

Micropolis(SimCity Classic의 실제 엔진)를 화면 없이 돌리면서 AI 시장이 도시를 운영합니다.
매달 기록하고, 결과를 **성장 영상과 웹 보고서**로 만듭니다.

## 모니터링하는 세 가지 방법

| 방법 | 필요한 것 | 내용 |
|---|---|---|
| 1. 웹 링크 | 브라우저 | claude.ai Artifact로 게시된 보고서 (소유자가 Share 메뉴로 공유해야 다른 사람이 열 수 있음) |
| 2. 저장소의 예시 | 브라우저 | `showcase/micropolis-seed2/index.html`. GitHub에서 ZIP으로 받아 압축을 풀고 더블클릭. 인터넷이 없어도 열림 (글꼴만 기본 글꼴로 대체) |
| 3. 직접 실행 | Linux 또는 Windows의 WSL, `g++`, Python 3.9 이상, numpy, Pillow, ffmpeg(영상용) | 원하는 조건으로 새 도시를 돌리고 보고서를 만듦 |

보고서에 들어 있는 것:
- 한 달에 한 프레임씩 그린 **성장 영상** (원작 타일 그래픽)
- 인구, 자금, R/C/I 수요, 범죄·오염·교통, 세율, 지가 차트. 점선은 전략 재검토 시점
- 매년 1월의 도시 지도
- **시장의 판단 기록**: 무엇을 왜 바꿨는지, 무엇을 예상했는지, 무엇을 모르는지, 그리고 다음 재검토에서 그 예상이 맞았는지 ("영상에서 보기" 버튼으로 그 시점으로 이동)

### 직접 실행 (Linux / WSL)
```
bash tools/setup_micropolis.sh          # 엔진을 받아 빌드 (약 10초, GPL-3.0이라 저장소에 포함하지 않음)
python -m mayor micropolis --years 20 --seed 2
# -> runs/micropolis-…/index.html, video.mp4
python -m mayor micropolis --reviewer llm --provider claude-code  # Claude Code 시장 (API 키 불필요)
python -m mayor micropolis --reviewer llm --provider gemini       # 다른 LLM (API 키 필요)
python -m mayor micropolis --report-only runs/micropolis-…        # 보고서만 다시 만들기
```
Windows에서 WSL 없이 실행하는 방법은 아직 확인하지 않았습니다.

### Claude Code를 시장으로 쓰기
`--provider claude-code`는 설치된 Claude Code CLI를 헤드리스로 호출합니다 (`claude -p --output-format json --tools ""`).
- API 키 없이 CLI의 로그인(구독)을 그대로 씁니다. 같은 PC(WSL)에서 `claude`에 한 번 로그인해 두면 됩니다.
- 모든 도구를 끄고 빈 임시 폴더에서 실행하므로, 시장 판단 외에 파일을 읽거나 바꾸지 않습니다.
- 재검토 1회에 15~20초 정도 걸립니다. 20년이면 재검토 20~30회입니다.
- `--model`로 모델을 고를 수 있습니다. 생략하면 CLI 기본 모델을 씁니다.

## 구조
```
매월:   관찰(엔진 값) → [재검토: 1년마다, 문제 신호가 있으면 앞당김] → 실행 → 결과 확인 → 기록
재검토: 규칙 또는 LLM이 "전략"(세율, 구역 비율, 예비 자금, 경찰·소방 비율, 발전소 종류,
        경기장·항구·공항, 토지 이용)만 정함. 매달의 건설은 일반 코드가 함
학습:   다음 재검토에서 지난 예측(지표별 증가·감소·유지)을 실제 값으로 채점하고, LLM에 그 기록을 보여 줌
```
- `mayor/micropolis/engine.py`: 엔진 래퍼, 수요 제한 규칙
- `planner.py`: 고정 격자 배치(도로, 전력선, 구역, 발전소, 특수 시설). 모든 건설은 결과를 확인함
- `strategy.py`: 전략 값과 매달 실행
- `review.py`: 규칙 시장, LLM 시장, 예측 채점
- `run.py`: 루프와 기록. `render.py`/`report.py`: 영상과 보고서

## 엔진에서 확인한 사실
- 도로는 전기를 전달하지 않습니다. 맞닿은 구역과 건물끼리 전기가 흐릅니다. 그래서 전력선 척추와 교차 전선을 둡니다.
- 석탄 발전소 1기가 약 48개 구역을 감당했고, 2기째를 짓자 정전이 사라졌습니다 (용량 문제였음).
- 새로 지은 구역은 엔진의 다음 전력 점검 전까지 "정전"으로 보입니다. 그래서 3개월 연속 정전일 때만 발전소를 짓습니다.
- **수요 제한** (엔진 `message.cpp`): 주민 500명 초과에 경기장이 없으면 주거 수요가 0으로 묶입니다. 공업 70 초과에 항구가 없거나, 상업 100 초과에 공항이 없어도 마찬가지입니다.
  이 규칙을 반영하자 최고 전략의 최종 인구가 5,420에서 18,300으로 올랐습니다 (시드 3개 평균).
- 세금은 매년 1월에 한 번 정산되고, 자금이 예비 자금 아래면 아무것도 짓지 않습니다.

## 실험 결과 (20년, 시드 8개)
| 시장 | 최종 인구 평균 | 중앙값 | 비고 |
|---|---|---|---|
| 고정 전략, 세율 7% | 11,395 | 11,550 | |
| 고정 전략, 세율 9% | 13,652 | 15,030 | 자금이 병목이라 세율이 조금 높은 편이 나았음 |
| 규칙 기반 재검토 | 6,600 | 6,210 | 예측 적중률 37%. **고정 전략보다 나쁨** |

- 단순한 규칙으로는 고정 전략도 이기지 못했습니다. 이 결과가 LLM 시장이 넘어야 할 기준선입니다.
- 공업 분리(`land_use: separated`, 공업을 주거에서 약 50칸 떨어진 아래쪽 구역에 배치):
  시드 8개, 세율 7% 기준으로 정점은 더 높았지만(평균 21,000 vs 18,300) 최종 인구는 낮았고(8,640 vs 11,395),
  평균 오염은 오히려 높았습니다(57 vs 45). 통근 거리가 늘어 교통 오염이 커졌을 가능성이 있지만 확인하지 않았습니다.
  - 처음 측정은 **전력 버그**가 있는 상태였습니다. 공업 구역이 빈 칸 너머에 있어 전기가 닿지 않았습니다.
    Claude Code 시장이 첫 판단부터 공업 분리를 고른 실행에서 정전 경고가 계속 나와 발견했고, 고친 뒤 다시 측정했습니다.
- 시드에 따라 결과 차이가 큽니다. 성장 → 쇠퇴 → 회복 주기가 자주 나타나고, 원인은 아직 확정하지 못했습니다
  (자금 정체, 범죄 증가, 지가 하락이 함께 나타남).
- `showcase/`의 예시는 시드 8개 중 하나(seed 2, 규칙 기반 시장)입니다. 성장과 쇠퇴, 회복이 모두 보여서 골랐습니다.

## Claude Code 시장 결과 (2026-10-10, 시드 1~4, 20년)
`--provider claude-code`, 모델 claude-sonnet-5-5, 재검토는 실행마다 25~27회였고 LLM 실패로 규칙에 넘긴 경우는 0회였습니다.
`experiments/micropolis/compare.py`로 같은 시드에서 비교했습니다.

| 시장 | seed 1 | seed 2 | seed 3 | seed 4 | 평균 최종 | 평균 정점 | 예측 적중률 |
|---|---|---|---|---|---|---|---|
| 고정 전략 (세율 7%) | 13,960 | 6,220 | 11,740 | 800 | 8,180 | 17,880 | — |
| 고정 전략 (세율 9%) | 18,760 | 14,500 | 21,640 | 14,240 | 17,285 | 21,295 | — |
| 규칙 기반 재검토 | 4,420 | 16,060 | 6,140 | 2,260 | 7,220 | 18,460 | 39% |
| **Claude Code 시장** | 10,400 | 4,000 | 1,360 | 980 | **4,185** | 9,895 | 43% |

**Claude Code 시장이 가장 나빴습니다.** 판단 기록을 보면 원인은 다음과 같습니다.
1. 초반 과소비: 세율 5%로 시작해 예비 자금을 1,500 → 800 → 500으로 낮추고 월 건설을 3~4건으로 늘렸습니다.
   2년 만에 자금이 바닥나고(1902년 자금 693), 세수가 유지비보다 적어 연간 현금 흐름이 −600 안팎이었습니다.
2. 프롬프트에 준 세율 사실이 "작은 시험에서 0%가 인구 최대"뿐이었습니다. 자금 압박이 있을 때는 9%가 가장 좋았다는 결과는 주지 않았습니다.
   시장은 "세율을 올리면 인구가 준다"는 근거로 낮은 세율을 고집했습니다. 추론은 주어진 정보와 일관됐지만 정보가 편향돼 있었습니다.
3. 이후는 다른 시장과 같은 성장 후 붕괴 패턴이었습니다.

다음 단계 후보: 지난 실행의 측정 결과(위 표와 같은 것)를 코드가 요약해 "교훈"으로 프롬프트에 넣고, 같은 시드로 다시 비교합니다 (로드맵 4단계).
판단 기록 원본: `showcase/claude-code-seed2/`(seed 2 전체), `experiments/micropolis/claude-code-runs/`(seed 1, 3, 4).

## 교훈(lessons) 실험 (2026-10-10)
지난 실행에서 배우게 하는 단계(로드맵 4단계)를 처음 시험했습니다.

교훈 파일 `experiments/micropolis/lessons/lessons-v1.json`(`python -m mayor lessons`로 생성)에 넣은 것:
1. **벤치마크**: 고정 전략을 세율만 바꿔(5/7/9/11%) 새 시드 9~16에서 20년씩 돌린 결과 (코드 측정)
   - 시드 9~16에서는 세율 5%가 가장 좋았습니다(최종 평균 14,232). 시드 1~8에서는 9%가 가장 좋았습니다.
     **세율 효과는 도시마다 크게 다르고, 어느 한쪽이 옳다고 말할 수 없습니다.**
2. **지난 Claude Code 실행 4개 요약** (코드 측정: 자금 고갈 시점, 건설이 멈춘 달 수 등)
3. **자기 성찰**: Claude Code가 자기 판단 기록을 읽고 쓴 "다음엔 이렇게" 규칙. 프롬프트에는 **가설**로 표시해 넣었습니다.

| 시장 (seed 1~4) | 평균 최종 | 20년 평균 인구 | 평균 정점 | 예측 적중률 |
|---|---|---|---|---|
| 고정 전략 (세율 9%) | 17,285 | 9,075 | 21,295 | — |
| 고정 전략 (세율 7%) | 8,180 | 7,585 | 17,880 | — |
| 규칙 기반 재검토 | 7,220 | 7,181 | 18,460 | 39% |
| Claude Code (교훈 없음) | 4,185 | 3,440 | 9,895 | 43% |
| Claude Code + 교훈 v1 | 3,170 | 3,222 | 10,855 | 39% |

새 도시(seed 5~6)에서도 교훈 v1 시장의 20년 평균 인구는 3,678로, 고정 7%(4,950)와 규칙 시장(6,727)보다 낮았습니다.

**교훈은 지켜졌지만 결과는 나아지지 않았습니다.**
- 지켜진 것: 예비 자금 1,000 이상, 월 건설 2건 이하. 자금이 1,000 아래로 처음 떨어진 시점이 1902~03년에서 1905~09년으로 늦어졌고,
  자금 부족으로 건설이 멈춘 달도 56~66개월에서 29~59개월로 줄었습니다.
- 그래도 정점 뒤 90% 안팎의 붕괴는 그대로였고, 정점 자체가 고정 전략보다 낮았습니다(약 11,000 vs 17,000~21,000).
- 가장 큰 차이로 보이는 것은 **구역 비율**입니다. Claude Code 시장은 초반에 엔진의 공업 수요가 높은 것을 보고
  공업 비중을 0.3으로 올렸습니다(지은 것: 주거 27~30 / 공업 18~21, 고정 전략은 주거 37 / 공업 12).
  앞선 실험에서도 주거 비중이 낮을수록 결과가 나빴습니다.
- **교훈 v1의 벤치마크는 세율만 바꿨습니다.** 실제로 차이를 만든 변수(구역 비율)는 교훈에 없었습니다.

다음 시도 후보: 시장이 실제로 쓰는 손잡이(구역 비율, 예비 자금, 건설 속도) 전부를 바꿔 본 벤치마크로 교훈 v2를 만들고, 같은 방식으로 다시 비교합니다.
판단 기록: `experiments/micropolis/claude-code-lessons-v1-runs/`.

## 교훈 v2 실험 (2026-10-11)
교훈 v1이 세율만 바꿔 본 탓에 실제로 차이를 만든 구역 비율을 놓쳤으므로, v2는 **시장이 쓰는 손잡이 전부**를 바꿔 측정했습니다.

1. **손잡이 격자 실험** (코드, 무료, 약 2분): 세율 3 × 주거 비율 4 × 예비 자금 2 × 월 건설 2 × 토지 이용 2 = 96가지 조합을
   새 시드 9~16에서 20년씩 실행했습니다. 지표는 20년 평균 인구입니다 (`lessons.benchmark_grid`).
   - 주거 비율 효과가 가장 큼: 0.4 → 2,408, 0.5 → 5,068, 0.6 → 7,792, 0.7 → 9,883
   - 월 건설 2건(7,286) > 4건(5,290). 세율 5%(7,022) > 7%(6,133) > 9%(5,709)
   - 공업 분리(7,115) > 혼합(5,461) 평균이지만, 최악의 조합에도 분리가 들어 있어 다른 손잡이와 상호작용이 있습니다
   - 최고 조합: 세율 5%, 주거 0.7, 예비 3,000, 월 2건, 분리 → 14,275 (시드별 10,137~17,105)
2. 지난 Claude Code 실행 10개의 요약 (무엇을 지었는지 포함)
3. 교훈 v1 실행 6개에 대한 자기 성찰 (6회 호출). 성찰도 "주거 비율 0.6~0.7, 이번 평균 0.48은 낮았다"를 짚었습니다.

| 시장 (seed 1~6) | 20년 평균 인구 | 평균 정점 | 평균 최종 | 예측 적중률 |
|---|---|---|---|---|
| 고정 전략: 격자 최고 조합 (시드 9~16에서 고름) | **13,524** | 23,277 | 5,400 | — |
| **Claude Code + 교훈 v2** | **10,615** | 19,790 | 6,290 | 41% |
| 규칙 기반 재검토 | 7,030 | 18,550 | 6,647 | 37% |
| 고정 전략 (세율 7%) | 6,706 | 17,500 | 9,180 | — |
| 고정 전략 (세율 9%) | 6,658 | 17,277 | 14,277 | — |
| Claude Code + 교훈 v1 | 3,374 | 11,167 | 2,800 | 38% |
| Claude Code (교훈 없음, seed 1~4만) | 3,440 | 9,895 | 4,185 | 43% |

- 교훈 v2로 Claude Code 시장의 20년 평균 인구가 **약 3배**가 됐고, 6개 도시 모두 8,556~12,182로 고르게 올랐습니다 (v1은 1,911~4,549).
  시장은 교훈대로 주거 목표를 약 0.68로, 토지 이용을 분리로 정했습니다.
- 고정 전략, 규칙 시장보다 나았지만 **격자 최고 조합을 그대로 고정한 전략(13,524)보다는 낮았습니다.** 지금은 측정 결과를 잘 따르는 수준이고,
  측정을 넘어서는 판단으로 이득을 보지는 못했습니다.
- 최종 인구(마지막 달 값)는 성장-붕괴 주기 때문에 들쭉날쭉해서, 비교는 20년 평균 인구로 했습니다. 정점 뒤 붕괴는 여전히 일어납니다.
- 주의: seed 1~6의 지난 실행 요약과 성찰이 교훈에 들어 있으므로 seed 1~6은 완전히 처음 보는 도시는 아닙니다.
  격자 실험은 seed 9~16에서 했습니다. 지도는 모두 같은 빈 땅이고 시드는 시뮬레이션의 무작위성만 바꿉니다.
- 실행 1회당 약 25회 호출, 약 26만 토큰, 정가 환산 약 $1.19 (교훈이 길어져 v1보다 토큰이 약 8% 늘었습니다).

## 새 도구(부서 예산·도로 간격)와 교훈 v3 (2026-10-11)

- **부서 예산 비율** (`road_funding`, `police_funding`, `fire_funding`, 0~100%): 엔진 C API에 `mp_set_budget`/`mp_budget_info`를

### 엔진 버그 수정 (중요)
헤드리스 엔진은 `updateFundEffects()`를 한 번도 부르지 않았습니다. 원래 게임에서는 예산 창을 닫을 때 UI가 불렀습니다.

### 이 실험에서 찾아 고친 실행기 버그 3개

2. **도로 수리가 성장을 깎음.** 도로 예산이 100% 미만이면 도로가 조금씩 잔해로 변합니다. 매달 이걸 고치느라 건설 몫을 썼고,
   고친 도로에는 교통이 늘었습니다. 엔진 소스(`scan.cpp`)에서 교통이 있는 도로 칸은 오염 50(가벼움)·75(많음)를 냅니다.

## 아직 안 된 것 / 확인하지 못한 것
- Gemini·OpenAI·Anthropic API 제공자는 키가 없어 실제로 호출하지 못했습니다. Claude Code(`claude -p`)로만 실제 실행했습니다.
- 부서별 예산 비율(경찰·소방·도로 %)은 원래 C API에 없어서 `tools/micropolis_patches/budget_capi.cpp` 패치로 노출했습니다. 이 패치는 원본 gymtropolis에 없습니다.
- 도로망은 고정 격자라 시장이 도로를 새로 낼 수 없습니다. 교통 문제에 대응할 수단이 없습니다.
- 지형(강·숲)과 재난은 `--terrain --disasters`로 켤 수 있습니다 (아래 '지형 + 재난' 참고). 엔진(`disasters.cpp` setFire)은 지도 전체에서
  무작위로 고른 칸이 건물일 때만 불을 냅니다. 그래서 작은 도시에서는 화재가 드물고, 도시가 커질수록 잦아집니다. 지진·토네이도·괴물이 실제로 일어나는 것은 확인하지 못했습니다.
- `saves/*.cty`는 원작과 같은 형식으로 저장한 도시입니다. 다른 Micropolis 프로그램에서 열리는지는 확인하지 않았습니다.
