# 로드맵: 관찰 → 판단 → 행동 → 평가 → 학습

원칙은 다음과 같습니다.
- 계산과 반복 작업은 코드로 처리하고, 대안 비교와 전략 결정에만 언어 모델을 씁니다.
- 각 단계가 실제 게임에서 작동하는 것을 확인한 뒤에 다음 단계로 넘어갑니다.

## 0단계: 환경 확인 (지금, 사용자 PC에서)
- `python -m mayor doctor`로 창 탐색과 캡처가 되는지 확인합니다.
- 검은 화면이면 창 모드를 찾습니다.
- 결과(`doctor.json`, `capture.png`)를 바탕으로 1단계 설정을 확정합니다.

## 1단계: 관찰과 기록 ✅ 프로토타입
- 화면 캡처 → 코드 점검 → OCR/비전 판독 → 상태 기록. 각 값에 출처와 확실성을 붙입니다.
- 다음 할 일: 실제 화면으로 ROI 보정, 비전 판독 정확도 측정 (OCR과 비전의 일치율 = 간이 정확도 지표)
- 확장 후보: 예산 창이나 데이터 지도(오염·교통 등)를 사람이 열어 두었을 때 그 내용도 읽기

## 2단계: 판단 (아직 조작 없음, "조언자 모드")
- `mayor/policy/` 아래에 둡니다.
- **규칙 엔진(코드)**: 자금 추세, 인구 성장률, R/C/I 수요 불균형 같은 지표를 계산합니다. 임계값을 넘으면 "검토 필요" 신호를 냅니다.
- **전략 LLM**: 신호가 있을 때만 호출합니다. 입력은 상태 요약(`CityState.summary()`)과 최근 추세, 과거 결정 기록입니다.
  출력은 대안 2~3개(기대 효과·위험·비용)와 선택 이유, 그리고 "모르는 정보와 그것을 확인하는 방법"입니다.
- 결정은 `decisions.jsonl`에 기록합니다. 결정 당시의 상태, 대안, 선택, 예상 결과를 함께 남깁니다.
- 이 단계에서는 사람이 결정을 읽고 직접 조작해 봅니다. AI 판단의 질을 조작 위험 없이 평가할 수 있습니다.

## 3단계: 행동 (게임 조작)
- 조작 수단은 실제로 확인한 것만 씁니다. 하나씩 시험해 `actions.md`에 "확인됨"으로 등록합니다.
  예: 특정 메뉴 클릭으로 예산 창 열기, 화면 이동 등
- 모든 행동은 **관찰 → 실행 → 재관찰 → 기대 결과와 비교** 순서로 진행합니다.
  예상과 다르면 즉시 멈추고 다시 관찰한 뒤 판단합니다. 무리하게 재시도하지 않습니다.
- 처음에는 되돌리기 쉬운 행동(창 열기·닫기, 세율 ±1)만 허용합니다.
  건설·철거처럼 되돌리기 어려운 행동은 나중에 허용하고, 처음에는 사람의 확인을 받습니다.
- 안전장치: 게임 창이 포그라운드가 아니거나 화면이 예상 상태가 아니면 아무것도 하지 않습니다.

## 4단계: 평가와 학습
- 결정 후 N개월(게임 시간)이 지나면 실제 결과를 `decisions.jsonl`의 예상과 비교해 `outcome`을 기록합니다.
- 다음 판단 때 비슷한 상황의 과거 결정과 결과를 프롬프트에 함께 넣습니다 (간단한 검색으로 충분).
- 쌓인 교훈을 "운영 원칙" 문서로 요약해 전략 LLM에 제공합니다. 이 요약은 사람이 검토할 수 있게 둡니다.
