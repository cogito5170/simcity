# 평가: LLM이 플레이하기 좋은 오픈소스 도시·전략 게임

평가일: 2026-10-10.
대상: Micropolis, LinCity-NG, OpenTTD, Freeciv, Unknown Horizons, cimulity.

평가 기준 (이 프로젝트의 목표 기준):
1. **코드로 관찰·조작할 수 있는가** (플러그인, API, 스크립팅). 화면 클릭에 의존하지 않아야 합니다.
2. **헤드리스·고속·결정적으로 돌아가는가.** 반복 실험, 대안 비교, 학습이 가능해야 합니다.
3. **"시장(mayor)" 주제에 맞는가.** 재정, 세율·예산, R/C/I 균형, 교통, 환경, 공공서비스가 있어야 합니다.
4. 무료 여부, 라이선스, 유지보수 상태, 설치 난이도

"직접 실행"은 이 클라우드(Linux)에서 실제로 빌드하고 돌려 본 것이고, "조사"는 문서와 소스 확인만 한 것입니다.

## 1. Micropolis (직접 실행)
- 1989년 SimCity 원작의 실제 C++ 엔진입니다 (MicropolisCore, GPL-3.0).
  - [gymtropolis](https://github.com/elmihailol/gymtropolis)(MIT 래퍼, 2026-09 첫 커밋)의 C API와 Python `ctypes`로 구동했습니다.
  - [MicropolisCore](https://github.com/SimHacker/MicropolisCore) 자체도 WebAssembly 빌드로 Node.js에서 헤드리스 실행을 지원합니다 (조사).
- 이 클라우드에서 `g++`로 11초 만에 빌드했습니다. Python은 numpy만 있으면 됩니다.
- 측정 (`experiments/micropolis/probe.py`):
  - 5년치 시뮬레이션이 약 5~10ms
  - 같은 입력이면 같은 결과 (결정적)
  - 세율 실험 (발전소 1개와 구역 8개짜리 같은 도시, 5년 후):

    | 세율 | 인구 | 범죄 | 점수 |
    |---|---|---|---|
    | 0% | 2,560 | 130 | 981 |
    | 7% | 2,280 | 121 | 882 |
    | 15% | 820 | 76 | 714 |
    | 20% | 320 | 49 | 519 |

    **정책이 결과를 실제로 바꾸고, 성장과 범죄 사이에 절충이 있습니다.**
  - 첫 배치에서는 도로가 전력을 전달하지 않아 10개 구역 중 9개가 정전이었습니다.
    `powered_zones`/`unpowered_zones` 지표로 원인을 알 수 있었고, 배치를 고치자 성장했습니다. **관찰 → 진단 → 수정** 루프가 실제로 돕니다.
- 읽을 수 있는 값: 자금, 인구, R/C/I 수요(valve), 세율, 현금 흐름, 평균 범죄·오염·지가·교통, 도시 점수,
  발전소·경찰·소방 수, 전력 공급 여부. 지도 오버레이 10종(오염, 범죄, 교통, 지가, 커버리지 등)
- 할 수 있는 행동: 구역, 도로, 철도, 전선, 발전소(석탄·원자력), 경찰, 소방, 공원, 경기장, 항구, 공항, 철거, 세율 설정, 재난 on/off, 저장과 불러오기(대안 분기)
- 부족한 점
  - 부서별 예산(경찰·소방·도로 %)은 엔진에 있지만 C API에 노출되어 있지 않습니다. C 함수 몇 줄을 추가하면 됩니다.
  - 빌드는 Linux 또는 WSL 기준입니다. Windows에서 직접 쓰려면 WSL을 쓰거나 빌드 방법을 바꿔야 합니다.
  - gymtropolis는 3주 된 신생 저장소입니다. 그래서 엔진(MicropolisCore)을 직접 감싸는 얇은 층을 우리가 갖는 편이 안전합니다.
  - 엔진이 GPL-3.0이므로, 함께 배포하는 바이너리는 GPL 조건을 따라야 합니다. 개인 실험에는 문제없습니다.

## 2. cimulity (직접 실행)
자세한 내용은 [EVAL_CIMULITY.md](EVAL_CIMULITY.md)에 있습니다.
- 장점: 명령 API, `inspectTile`로 원인 진단, 결정적 실행, 저장 분기
- 약점: 세율·예산·조례 없음, 오염·범죄·재난 없음, 1인 개발 중이라 API가 바뀔 수 있음

## 3. OpenTTD (조사)
- AI API와 GameScript(Squirrel 언어), 그리고 관리 포트(TCP 프로토콜)가 공식으로 있습니다. 헤드리스 전용 서버도 있습니다.
- LLM 에이전트용 벤치마크 [nttd](https://pypi.org/project/nttd/)가 OpenTTD 전용 서버를 구조화된 JSON API로 감싸 제공합니다.
- 다만 플레이어는 **운송 회사**입니다. 도시는 스스로 자라고, 세율·구역·공공서비스 같은 시장의 결정이 없습니다.

## 4. Freeciv (조사)
- [CivRealm](https://github.com/bigai-ai/civrealm)(ICLR 2024)이 강화학습용과 언어모델용 인터페이스를 모두 제공합니다. Docker와 freeciv-web이 필요합니다.
- 도시 관리는 있지만 문명 전체(외교, 전쟁, 기술)가 범위라 "시장" 주제에는 너무 넓습니다.
  논문에서도 LLM 에이전트가 전체 게임에서는 거의 진전을 못 했다고 보고합니다.

## 5. LinCity-NG (조사)
- 활발히 유지보수 중입니다 (최신 2.15.0, SDL3로 이전). 자원과 지속가능성 중심의 경제 시뮬레이션이라 주제는 잘 맞습니다.
- 스크립팅이나 외부 API를 찾지 못했습니다. 쓰려면 C++ 코드를 직접 고쳐 API를 만들어야 하고, 게임이 GUI와 묶여 있어 헤드리스화도 작업이 필요합니다.

## 6. Unknown Horizons (조사)
- Python으로 만든 Anno 풍 건설 게임이라 내부 AI 플레이어 코드를 참고할 수 있습니다.
- 본가의 마지막 공식 릴리스는 2019.1입니다. 2026년에 커뮤니티 포크 릴리스가 있습니다.
  FIFE 엔진 의존성이 무겁고, 주제가 무역·정착 중심이라 시장 정책과는 거리가 있습니다.

## 권장
1. **Micropolis를 주 실험장으로 씁니다.** 시장 주제의 판단 요소(재정·세율, R/C/I 균형, 교통, 오염, 범죄, 공공서비스, 재난)가 모두 있습니다.
   - 얇은 Python 어댑터 하나(관찰·행동·시간 진행·저장 분기)를 만들고, 현재의 상태 모델(값마다 출처와 확실성)과 기록 형식에 연결합니다.
   - 부서 예산 함수를 C API에 추가합니다.
2. cimulity는 두 번째 어댑터 후보로 둡니다. API가 깔끔해 구조 검증용으로 좋습니다.
3. SimCity 3000은 설치가 확인되면, 같은 어댑터 인터페이스(화면 판독 또는 플러그인)로 나중에 연결합니다.
